## Methodology

| | |
|---|---|
| Hardware | AMD Ryzen 9 9950X3D 16-Core Processor · Linux 7.2.11-arch1-1 · governor `performance` · SMT on |
| Runtimes | Bun 1.4.4 · Node v26.13.0 · postgres (PostgreSQL) 18.3 (Debian 18.3-1.pgdg13+1) |
| Server | one at a time, logical CPU 9 (sibling 25 not used by the harness), systemd scope: MemoryMax=2G, MemorySwapMax=0, taskset 1 logical CPU |
| Lifecycle | one fresh process per target, reused for all of its scenarios |
| Warm-up | this sweep split 120 s evenly over each target's routes (round(120 / routes) s each); discarded |
| Load generator | `taskset -c 1,2,17,18 wrk -t2 -c128 -d<N>s --latency --timeout 10s`, 180s per scenario |
| Repetitions | 1 per scenario, single observation, no spread available |
| Database | PostgreSQL, cpuset `3-7,19-23`, `synchronous_commit = off`, pool size 20, 10,000 seeded rows, writes truncated before each write scenario |
| Generated | 2026-11-01T08:34:15.376Z |

::: warning
The `/db/*` layer is **not** uniform across apps — it is each stack's idiomatic choice
(`pg`, `Bun.sql`, TypeORM, drizzle). Every table below labels it.
:::
